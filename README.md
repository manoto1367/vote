# سامانه یکپارچه انتخابات مدارس

رأی‌گیری آنلاین چندمدرسه‌ای با **Supabase**؛ یک صفحهٔ HTML ساده، بدون نیاز به سرور و بدون build.

</div>

---

## ویژگی‌ها

- چهار نقش با دسترسی جدا: **ادمین ارشد ← مدیر کل ← مدیر مدرسه ← رأی‌دهنده**
- ادمین ارشد برای مدیران کل نام کاربری و رمز می‌سازد و هر زمان **دسترسی هر مدیر را قطع یا وصل** می‌کند
- برای هر مدیر کل و هر مدرسه یک **کلید دسترسی** در پنل ادمین ارشد هست؛ قطع مدرسه، لینک رأی‌دهندگانش را هم می‌بندد
- **کلید قطع سراسری**: با یک کلیک ورود مدیران، مدارس و لینک رأی‌دهندگان بسته می‌شود (نشست‌های فعال بلافاصله پاک می‌شوند)
- هر مدیر کل فقط مدارس خودش را می‌بیند؛ هر مدرسه لینک اختصاصی رأی‌گیری دارد
- یک کد ملی در هر مدرسه فقط یک‌بار رأی می‌دهد؛ کد پیگیری رأی صادر می‌شود
- نمودار، رتبه‌بندی و خروجی CSV
- رابط فارسی راست‌به‌چپ و واکنش‌گرا (موبایل و دسکتاپ)

## نقش‌ها

| نقش | ساخته می‌شود توسط | کارها |
|---|---|---|
| ادمین ارشد | اولین اجرای سامانه | ساخت مدیر کل، کلید دسترسی هر مدیر و هر مدرسه، رمز جدید، کلید قطع سراسری |
| مدیر کل | ادمین ارشد | ساخت مدارس، مشاهدهٔ داشبورد و نتایج مدارس خودش |
| مدیر مدرسه | مدیر کل | ورود با لینک `?schooladmin`؛ کاندیداها، تنظیمات، باز/بستن رأی‌گیری، لینک رأی‌دهندگان |
| رأی‌دهنده | — | ثبت رأی با لینک مدرسه (`?school=...`) |

## ساختار پروژه

```
├── index.html            برنامهٔ کامل (HTML + CSS + JS)
├── config.js             آدرس و کلید Supabase
├── config.example.js     نمونهٔ تنظیمات
├── site.webmanifest      نصب به‌صورت PWA
├── assets/               آیکون‌ها (SVG, PNG, ICO)
└── supabase/schema.sql   جدول‌ها، امنیت (RLS) و توابع سرور
```

## راه‌اندازی

### ۱) پایگاه داده

1. در [Supabase](https://supabase.com) یک پروژه بسازید.
2. در **SQL Editor** محتوای [`supabase/schema.sql`](supabase/schema.sql) را یک‌بار اجرا کنید (اجرای دوباره بی‌خطر است).

### ۲) تنظیمات اتصال

`config.example.js` را به `config.js` کپی کنید و مقادیر را بگذارید (Supabase → Project Settings → API):

```js
window.APP_CONFIG = {
  SUPABASE_URL: 'https://YOUR-PROJECT-REF.supabase.co',
  SUPABASE_KEY: 'sb_publishable_xxxxxxxx'
};
```

> کلید **publishable** عمداً عمومی است و داخل مرورگر قرار می‌گیرد. هرگز کلید `service_role` یا `secret` را در این پروژه نگذارید.

### ۳) اجرا

محلی:

```bash
python3 -m http.server 8000
# سپس http://localhost:8000
```

یا روی **GitHub Pages**: Settings ← Pages ← Deploy from a branch ← `main` / root.

### ۴) اولین استفاده

1. صفحه را باز کنید؛ ابتدا فرم **ساخت حساب ادمین ارشد** نمایش داده می‌شود (فقط یک‌بار).
2. با ادمین ارشد وارد شوید و **مدیر کل** بسازید. لینک ورود مدیر کل (`?manager`) همان‌جا آماده است.
3. مدیر کل مدرسه می‌سازد و لینک ورود مدیران مدارس (`?schooladmin`) را از تب «مدیریت مدارس» به آن‌ها می‌دهد.
4. مدیر مدرسه با آن لینک وارد می‌شود، کاندیدا اضافه و رأی‌گیری را باز می‌کند و لینک رأی‌دهندگان را پخش می‌کند.

## امنیت

- همهٔ جدول‌ها RLS دارند و **هیچ policy ای ندارند**؛ مرورگر با کلید عمومی مستقیم به جدول‌ها دسترسی ندارد. همه‌چیز از توابع `mc_*` (SECURITY DEFINER) می‌گذرد و توابع داخلی برای کاربر عمومی بسته‌اند.
- رمزها با bcrypt هش می‌شوند؛ نشست‌ها توکن تصادفی ۲۵۶ بیتی با انقضا دارند.
- ۵ ورود ناموفق پشت‌سرهم، همان نام کاربری را ۱۰ دقیقه قفل می‌کند.
- کد ملی با HMAC و کلید مخفی سمت سرور هش می‌شود و به‌صورت خام ذخیره نمی‌شود. کد ملی از نظر الگوریتم کنترل ایران اعتبارسنجی می‌شود.
- کاندیدایی که رأی دارد قابل حذف نیست.

### محدودیت‌های شناخته‌شده

- نشست‌ها در `sessionStorage` مرورگر نگه داشته می‌شوند و با بستن تب پاک می‌شوند.
- **رأی کاملاً ناشناس نیست**: نام رأی‌دهنده (`mc_voters`) با انتخاب‌هایش (`mc_votes`) از طریق `voter_id` به هم وصل است و کسی که به پایگاه داده دسترسی مستقیم دارد می‌تواند ببیند چه کسی به چه کسی رأی داده است. مدیران داخل برنامه چنین گزارشی نمی‌بینند. اگر انتخابات باید ناشناس باشد، این پیوند را حذف کنید (مثلاً فقط کد پیگیری و آرای بدون شناسه رأی‌دهنده ذخیره شود).
- هیچ محدودیت نرخ (rate limit) سراسری روی ثبت رأی وجود ندارد؛ برای انتخابات بزرگ، محافظت در سطح پروژهٔ Supabase یا CDN اضافه کنید.

## ابزارهای حذف و پاک‌سازی مدیریتی

برای فعال‌کردن قابلیت‌های جدید روی نسخه‌ای که از قبل نصب شده است:

1. فایل `migration_delete_tools.sql` را در SQL Editor پروژه Supabase اجرا کنید.
2. فایل `index.html` به‌روزشده را همراه با فایل‌های قبلی روی GitHub Pages منتشر کنید.
3. از پنل ادمین ارشد، مدیرکل یا مدیر مدرسه، ابزارهای حذف و پاک‌سازی متناسب با سطح دسترسی در دسترس هستند.

**توجه:** حذف مدرسه یا مدیرکل، اطلاعات وابسته به آن‌ها را نیز حذف می‌کند. پاک‌سازی نتایج، رأی‌ها و اطلاعات رأی‌دهندگان را حذف می‌کند اما مدارس و کاندیداها را نگه می‌دارد. این عملیات برگشت‌پذیر نیست؛ پیش از اجرا از پایگاه داده نسخه پشتیبان تهیه کنید.


## تغییر نام کاربری و رمز ادمین ارشد

در پنل ادمین ارشد بخش «حساب ادمین ارشد» اضافه شده است: تغییر نام کاربری و تغییر رمز عبور (هر دو با تأیید رمز فعلی). همچنین کنار هر مدیر کل دکمهٔ «تغییر نام کاربری» هست (تغییر رمز مدیر کل از قبل با «رمز جدید» وجود داشت).

برای نسخه‌ای که از قبل نصب شده است:

1. فایل `migration_super_account.sql` را یک‌بار در SQL Editor پروژه Supabase اجرا کنید (در `schema.sql` هم گنجانده شده است).
2. `index.html` به‌روزشده را منتشر کنید.

با تغییر رمز، نشست‌های دیگر ادمین ارشد بسته می‌شود و نشست فعلی باقی می‌ماند.
